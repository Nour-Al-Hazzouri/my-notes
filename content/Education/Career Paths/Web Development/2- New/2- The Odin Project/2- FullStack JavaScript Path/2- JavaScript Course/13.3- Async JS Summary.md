### 1. Callbacks: The Foundation of Async

Callbacks are the primary way Node.js and JavaScript handle tasks that take time, such as reading a file or making a network request. Instead of the computer waiting and stopping all other work (blocking), it "kicks off" the task and moves to the next line of code. You provide a function—the callback—that the system runs once the slow task is finished.

**Code Example: Error-First Callback**

```js
const fs = require('fs');

fs.readFile('data.txt', 'utf8', (err, data) => {
  if (err) {
    return console.error("Failed:", err);
  }
  console.log("Data:", data);
});
```

**Line-by-Line Explanation:**

- `const fs = require('fs');`: Imports the native Node.js File System module.
- `fs.readFile('data.txt', 'utf8', (err, data) => {`: Calls an asynchronous method. The **native functionality** here is that the third argument must be a function. This function is not run immediately; it is handed to the operating system to be called later.
- `(err, data)`: This follows the **"Node style" error-first convention**. The first argument is reserved for an error object (if the task fails), and the second is for the successful data.
- `if (err) { return console.error(...); }`: A standard check to see if the error argument is not null. If it exists, we stop the function and report the failure.
- `console.log("Data:", data);`: This only runs if the error check passes, ensuring we only use the data once it is safely retrieved.
- **Connection:** The `readFile` method triggers a background operation, allowing the rest of the script to continue. Only when the OS reports the file is ready does the "callback" function enter the queue to be executed.

---

### 2. Promises: The Modern Commitment

A Promise is a special JavaScript object that represents the eventual completion (or failure) of an asynchronous operation. It acts as a link between "producing code" (the task) and "consuming code" (the reaction). Promises were designed to solve "callback hell," where multiple nested callbacks make code hard to read.

**Code Example: Promise Constructor and Internal State**

```js
const myPromise = new Promise((resolve, reject) => {
  const success = true;
  if (success) resolve("Success!");
  else reject(new Error("Failure"));
});

myPromise.then(val => console.log(val));
```

**Line-by-Line Explanation:**

- `const myPromise = new Promise((resolve, reject) => {`: Creates a new Promise object. The **executor function** inside runs **automatically and immediately**.
- `resolve` and `reject`: These are **native callbacks** provided by the JS engine. They change the internal properties of the promise.
- `resolve("Success!");`: Calling this changes the internal `state` property to "fulfilled" and the `result` property to "Success!".
- `reject(new Error("Failure"));`: If called, this would change the `state` to "rejected" and the `result` to the error object.
- **"First Call Wins" Rule:** Once `resolve` or `reject` is called, the promise is **settled**, and any further calls are ignored.
- `myPromise.then(val => console.log(val));`: Registers a "reaction." The `.then` method waits for the internal state to change before scheduling its code to run.

---

### 3. Parallelism and Competition

When handling multiple promises, JavaScript provides static methods to manage them as a group.

**Code Example: `Promise.all` and `Promise.race`**

```js
const p1 = Promise.resolve("Fast");
const p2 = new Promise(res => setTimeout(() => res("Slow"), 1000));

Promise.all([p1, p2]).then(([res1, res2]) => console.log(res1, res2));
Promise.race([p1, p2]).then(winner => console.log(winner));
```

**Line-by-Line Explanation:**

- `Promise.all([p1, p2])`: Takes an array of promises and waits for **all** of them to settle as fulfilled. If one fails, the whole thing rejects.
- `.then(([res1, res2]) => ...)`: The result is an array in the **exact same order** as the input. We use **destructuring sugar** to assign variables to each result.
- `Promise.race([p1, p2])`: Returns the result of the **first** promise to settle (either resolve or reject).
- `winner => console.log(winner)`: Only "Fast" will be logged because it finished before the 1-second timer of `p2`.

---

### 4. The JavaScript Environment (Event Loop)

JavaScript is **single-threaded**, meaning it has one **Call Stack** and can only execute one thing at a time. It handles multiple tasks through the **JavaScript Runtime**, which includes the Engine (V8), Web APIs, and Queues.

**Code Example: Microtask vs. Task Priority**

```js
console.log("Start");

setTimeout(() => console.log("Task Queue"), 0);

Promise.resolve().then(() => console.log("Microtask Queue"));

console.log("End");
```

**Line-by-Line Explanation:**

- `console.log("Start")`: Executed immediately on the **Call Stack**.
- `setTimeout(..., 0)`: This is a **Web API** call. The engine hands the timer to the browser, which immediately puts the callback in the **Task Queue**.
- `Promise.resolve().then(...)`: The promise resolves immediately, and its handler is put in the **Microtask Queue**.
- `console.log("End")`: Executed immediately on the Call Stack.
- **The Event Loop:** Once the stack is empty, it checks the **Microtask Queue** first. It **must empty the entire Microtask Queue** before moving to the Task Queue.
- **Result:** "Start", "End", "Microtask Queue", "Task Queue".

### Revision Summaries

**Idea: Callbacks** - Non-blocking functions that are executed at a later time once an asynchronous task completes.

```js
function callback(err, data) { if(!err) console.log(data); }
fs.readFile('path', 'utf8', callback);
```

`fs.readFile` is called and immediately returns control to the script. The `callback` is stored and only executed by Node once the OS confirms the file is read. It follows the **error-first convention** where the first argument is always the error check.

**Idea: The Promise Object** - A link between producing code and consuming code with internal `state` and `result` slots.

```js
const p = new Promise((res, rej) => res("Result"));
p.then(val => console.log(val)).catch(err => console.log(err));
```

The constructor runs immediately. `res` (resolve) and `rej` (reject) are native functions that change the internal state from "pending" to "settled." Once settled, the result is final.

**Idea: The Microtask Queue** - A high-priority queue specifically for Promise reactions and `queueMicrotask` calls.

```js
Promise.resolve().then(() => console.log("I win"));
setTimeout(() => console.log("I lose"), 0);
```

The Event Loop prioritized the Microtask Queue over the Task (Callback) Queue. Every single microtask must be finished before the browser even looks at the next timer or click event in the task queue.

**Idea: The Event Loop & Call Stack** - The mechanism that monitors the stack and decides when to move tasks from queues into the execution thread.

```
// Priority: Call Stack > Microtasks > Render > Tasks
```

JavaScript is single-threaded; the Call Stack records where we are in the program. If the stack is blocked by slow code, the Event Loop cannot move new tasks or render the UI, causing the browser to freeze.

### Full Code Picture: The Integrated Async Flow

```js
const fs = require('fs'); // Environment: Node.js C++ APIs

console.log("1. Script Start"); // Call Stack: Immediate

// A Promise wrapping a legacy callback
const readFilePromise = (path) => {
  return new Promise((resolve, reject) => {
    console.log("2. Executor running"); // Constructor runs immediately
    fs.readFile(path, 'utf8', (err, data) => {
      if (err) reject(err); // Becomes a Microtask later
      else resolve(data);
    });
  });
};

setTimeout(() => console.log("3. Task Queue (Timer)"), 0); // Web API -> Task Queue

readFilePromise('num.txt')
  .then(data => console.log("4. Microtask (Promise):", data)) // -> Microtask Queue
  .catch(err => console.error(err.message))
  .finally(() => console.log("5. Cleanup complete")); // Pass-through handler

console.log("6. Script End"); // Call Stack finishes

// Execution Order: 1, 2, 6, 4, 5, 3
```
