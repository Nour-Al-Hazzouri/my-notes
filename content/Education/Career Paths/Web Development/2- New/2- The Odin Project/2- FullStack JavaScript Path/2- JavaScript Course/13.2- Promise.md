### 1. The Concept: Producing vs. Consuming Code

A **Promise** is a special JavaScript object that links "producing code" (which takes time, like a singer recording a song) and "consuming code" (the fans waiting to hear it). It represents an eventual completion or failure of an asynchronous operation.

**Internal States of a Promise:**

- **Pending:** Initial state, neither fulfilled nor rejected.
- **Fulfilled:** Meaning the operation completed successfully.
- **Rejected:** Meaning the operation failed.
- **Settled:** A term used for a promise that is no longer pending (it is either fulfilled or rejected).

### 2. Creating a Promise: The Constructor

You create a promise using the `new Promise` constructor. This constructor takes a function called the **executor**, which runs **automatically and immediately** when the promise is created.

```js
const myPromise = new Promise((resolve, reject) => {
  const success = true;

  if (success) {
    resolve("Video Uploaded!");
  } else {
    reject(new Error("Upload Failed"));
  }
});
```

**Code Explanation:**

- `const myPromise = new Promise((resolve, reject) => {`: This creates the promise object. The constructor passes two **native callbacks** provided by the JavaScript engine: `resolve` and `reject`.
- `if (success) { resolve("Video Uploaded!"); }`: If the task is successful, you call `resolve(value)`. This changes the internal state to "fulfilled" and the result to the value provided.
- `else { reject(new Error("Upload Failed")); }`: If it fails, you call `reject(error)`. It is a developer convention to use `Error` objects for rejections.
- **Connection:** The executor performs the job and then uses these native functions to signal the final state. Only the first call to `resolve` or `reject` counts; any further calls are ignored.

### 3. Consuming a Promise: Then, Catch, and Finally

Once a promise is "settled," consuming functions can subscribe to the result using three main methods.

```js
myPromise
  .then((data) => console.log(data))
  .catch((err) => console.error(err.message))
  .finally(() => console.log("Cleanup complete"));
```

**Code Explanation:**

- `.then((data) => ...)`: This registers a "fan." It runs when the promise resolves. The `data` variable is the value passed to the `resolve` function.
- `.catch((err) => ...)`: This is a shorthand for handling errors. It runs if the promise rejects or if an error is thrown inside a `.then` block.
- `.finally(() => ...)`: This runs regardless of the outcome (success or failure). It is used for cleanup, like stopping a loading spinner.
- **Native Convention:** A `finally` handler has **no arguments** and doesn't know the outcome of the promise; it simply "passes through" the result or error to the next handler.

### 4. Behind the Scenes: The Microtask Queue

This is where promise execution gets special. Unlike regular callbacks (from `setTimeout`), promise reactions are added to the **Microtask Queue**.

**Native Priority:** The Event Loop prioritizes the Microtask Queue over the regular Task (Callback) Queue. The engine must empty the entire Microtask Queue before it allows anything else (like a timer or a click event) to run.

```js
console.log("Start");

setTimeout(() => console.log("Timer Task"), 0);

Promise.resolve().then(() => console.log("Promise Microtask"));

console.log("End");
```

**Code Explanation:**

1. **"Start"** and **"End"** log immediately (Call Stack).
2. `setTimeout` puts its callback in the **Task Queue**.
3. `Promise.resolve().then` puts its callback in the **Microtask Queue**.
4. Even though the timer is 0ms, the Event Loop checks the Microtask Queue first once the stack is empty.
5. **Result:** "Start", "End", "Promise Microtask", "Timer Task".

### 5. Parallelism: All vs. Race

When dealing with multiple promises at once, JavaScript provides two powerful static methods.

```js
const p1 = Promise.resolve("Video 1");
const p2 = Promise.resolve("Video 2");

Promise.all([p1, p2]).then((results) => {
  console.log(results); // ["Video 1", "Video 2"]
});

Promise.race([p1, p2]).then((winner) => {
  console.log(winner); // "Video 1"
});
```

**Code Explanation:**

- `Promise.all([...])`: Runs all promises in parallel. It waits for **all** to succeed and returns an array of results in the same order they were provided. If any one fails, the whole thing rejects immediately.
- `Promise.race([...])`: Returns the result or error of the **first** promise that settles.
- **Connection:** These methods treat an array of asynchronous tasks as a single logic block, allowing for faster performance by not waiting for one task to finish before starting the next.

### Summary Revision

**Promise Creation** - A constructor that wraps an asynchronous task and provides success/failure triggers.

```js
const p = new Promise((resolve, reject) => resolve("Done"));
```

`new Promise` executes immediately; `resolve` and `reject` are native callbacks that change the internal `state` and `result` of the object.

**Promise Consumers** - Methods attached to a promise to handle its eventual success, failure, or general completion.

```js
p.then(res => res).catch(err => err).finally(() => {});
```

`.then` handles success; `.catch` handles errors; `.finally` runs regardless but does not receive the result and passes it down the chain instead.

**Microtask Priority** - The internal queue for promise reactions that is processed before regular timers and browser events.

```js
Promise.resolve().then(() => console.log("Priority"));
```

Reactions inside `.then` are scheduled in the Microtask Queue, which the Event Loop prioritizes over the standard Callback/Task Queue.

**Chaining** - The ability for `.then` to return a new promise, allowing tasks to be written in a "flat" vertical order.

```js
p.then(v => v + 1).then(v => console.log(v));
```

Because each `.then` returns a new promise object, we avoid "callback hell" (deeply nested code) and can handle data incrementally in a non-blocking way.

**Full Picture Code Example:**

```js
const fetchUser = (id) => {
  return new Promise((resolve, reject) => {
    // Simulating a network request
    setTimeout(() => {
      if (id) resolve({ id, name: "Kyle" });
      else reject(new Error("No ID"));
    }, 1000);
  });
};

fetchUser(1)
  .then(user => {
    console.log("User:", user.name);
    return user.id; // Passing ID to the next link
  })
  .then(id => console.log("Fetching profile for ID:", id))
  .catch(err => console.error(err.message))
  .finally(() => console.log("Process Finished"));
```
