Space complexity is a metric used in algorithm development to measure how much storage space (primary memory) an algorithm needs in relation to the size of its inputs. While time complexity focuses on speed, space complexity focuses on how memory usage grows as you feed the algorithm more data.

### 1. The Core Components of Space Complexity

When measuring space, we look at two main parts:

- **Input Space:** The memory taken up by the data passed into the function (like an array or object).
- **Auxiliary Space:** The **extra** or temporary space used by the algorithm during its execution, such as temporary variables or the call stack.

**Total Space Complexity = Input Space + Auxiliary Space**.

---

### 2. Measuring Space with Big O

We measure space using the same Big O notations as time complexity. We ignore constants and focus on the growth rate. For example, if an algorithm creates 3 temporary variables regardless of input size, we drop the "3" and call it **O(1)**.

#### **O(1) - Constant Space**

An algorithm has O(1) space complexity if it uses a fixed amount of memory that does not change, no matter how large the input is.

**Code Example:**

```js
function multiplyNumbers(num1, num2) {
  const result = num1 * num2; // Creates 1 variable
  return result;
}
```

**Line-by-Line Dive:**

1. `function multiplyNumbers(num1, num2)`: The function accepts two inputs.
2. `const result = num1 * num2`: We create exactly one variable, `result`, to store the product.
3. `return result`: We return that single value. **Connection:** No matter if the numbers are 5 or 5,000,000, we only ever store one `result` variable in memory. This is a "constant" amount of space.

#### **O(N) - Linear Space**

Space usage is O(N) when the memory required grows in direct proportion to the size of the input. This usually happens when you create a new data structure (like an array or object) to store data based on the input.

**Code Example:**

```js
function duplicateArray(arr) {
  let newArray = []; // Start an empty structure
  arr.forEach(item => {
    newArray.push(item); // Grow based on input size
  });
  return newArray;
}
```

**Line-by-Line Dive:**

1. `let newArray = []`: We initialize a new, empty array.
2. `arr.forEach(...)`: We look at every item in the input array `arr`.
3. `newArray.push(item)`: For every 1 item in the input, we add 1 item to our `newArray`. **Connection:** If the input `arr` has 10 items, `newArray` uses 10 units of space. If `arr` has 1,000,000 items, `newArray` uses 1,000,000 units. The space grows linearly (O(N)) with the input size.

### 3. Auxiliary Space Analysis: In-Place vs. New Memory

This analysis is useful for seeing how much **extra** memory an algorithm uses.

**Code Example (In-Place vs. Copying):**

```js
// Function A: O(1) Auxiliary Space (In-Place)
function squareInPlace(arr) {
  for (let i = 0; i < arr.length; i++) {
    arr[i] = arr[i] * arr[i]; // Modifies original
  }
  return arr;
}

// Function B: O(N) Auxiliary Space (Creating a Copy)
function squareWithCopy(arr) {
  return arr.map(num => num * num); // Creates brand new array
}
```

**Line-by-Line Dive (Function A):**

- `arr[i] = arr[i] * arr[i]`: This changes the data inside the existing memory of the input. We don't create a new array, so the **extra** space is O(1).

**Line-by-Line Dive (Function B):**

- `arr.map(...)`: The `map` method automatically creates a brand new array of the same length as the input. This takes O(N) **extra** space.

### 4. Recursion and the Call Stack

Recursion adds a unique layer to space complexity because of the **Call Stack**—a structure that tracks active functions. Every time a function calls itself, a "stack frame" is added to memory to remember where the computer was.

- **Analogy:** Imagine a pile of rocks. Every recursive call adds 2 rocks to your hands. You can't put any rocks down until the very last call finishes. The deeper the recursion, the heavier the pile (the higher the space complexity).
- **Analogy:** A shopping cart at a checkout. Items are scanned from the top (Last In, First Out). The space used is the full cart waiting to be processed.

**Code Example:**

```js
function countdown(n) {
  if (n <= 0) return; // Base Case
  countdown(n - 1); // Recursive Step
}
```

**Line-by-Line Dive:**

1. `if (n <= 0) return`: The "stop" condition.
2. `countdown(n - 1)`: The function calls itself. If `n` is 100, the computer must "remember" 100 unfinished versions of `countdown` on the stack at once. **Connection:** The space complexity is O(N) because the stack grows as deep as the input number `n`.

### Big O Space Complexity Summary Table

|Big O Notation|Meaning (Space Wise)|Example Scenario|
|:--|:--|:--|
|**O(1)**|**Constant:** Space does not change with input size.|Simple math, returning a single variable, or in-place modification.|
|**O(log N)**|**Logarithmic:** Space grows very slowly relative to input.|Binary search (if recursive) or storing certain index bits.|
|**O(N)**|**Linear:** Space grows directly with input size.|Creating a copy of an array or a recursive call stack `n` deep.|
|**O(N²)**|**Quadratic:** Space grows by the square of the input.|Creating a 2D matrix (like a grid) based on input length.|
|**O(2ⁿ)**|**Exponential:** Space doubles with each addition to input.|Recursive algorithms that branch out multiple times (like some Fibonacci solvers).|

### Revision Summary

**Space Complexity** - A measure of the total memory (input + extra) an algorithm needs as inputs grow.

**Code Example:**

```js
function getSum(arr) {
  let sum = 0;
  for (let i = 0; i < arr.length; i++) {
    sum += arr[i];
  }
  return sum;
}
```

**Code Explanation:**

- `let sum = 0`: This is a single variable, which is native to the function's logic to store the result. It is **O(1)** because we only need one "slot" for `sum` no matter how big the array is.
- `let i = 0`: This is a loop index. While technically it takes bits to store (log N), developers conventionally treat it as **O(1)** because it occupies a single variable slot.
- The function does not create any new arrays or data structures, so its **Auxiliary Space** is O(1).

**Full Picture Code Example:**

```js
function categorizeNumbers(arr) {
  // Input: Array of N numbers
  let evens = []; // O(N) potentially (if all are even)
  let odds = [];  // O(N) potentially (if all are odd)

  arr.forEach(num => {
    if (num % 2 === 0) {
      evens.push(num);
    } else {
      odds.push(num);
    }
  });

  return { evens, odds }; // Total Space: O(N)
}
```

**Explanation:** Here, the total space used is O(N) because the new arrays (`evens` and `odds`) will combined hold exactly `N` elements, growing linearly with the input `arr`.
